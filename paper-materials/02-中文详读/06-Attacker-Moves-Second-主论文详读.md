# 论文详读：攻击者后手出招：更强的自适应攻击可绕过 LLM 越狱与提示注入防御

> 会议：USENIX Security 2026（35th，2026-08-12~14，Baltimore） | 英文原题：The Attacker Moves Second: Stronger Adaptive Attacks Bypass Defenses Against LLM Jailbreaks and Prompt Injections | 作者：Milad Nasr, Nicholas Carlini (Anthropic)、Chawin Sitawarin (Google DeepMind)、Sander V. Schulhoff (HackAPrompt/MATS)、Florian Tramèr (ETH Zurich) 等十余位跨机构作者 | [论文页面](https://www.usenix.org/conference/usenixsecurity26/presentation/nasr)

## 一句话概括

作者用一个统一的"提出—打分—选择—更新"自适应攻击框架（梯度下降、强化学习、进化搜索、人类红队四类实例化），将 12 个近年 LLM 越狱/提示注入防御逐一击穿——大部分防御的攻击成功率（ASR）被推到 90% 以上，而这些防御在原论文中大多报告接近 0% 的 ASR，以此论证：**不做强自适应攻击评估的防御评测是无效的，测的只是攻击者的弱，不是防御的强**。

## 研究背景与动机

对抗 ML 的历史教训反复出现：对抗样本、后门、投毒、机器遗忘、成员推断等领域的顶会防御，后来都被"针对防御设计做适配"的攻击攻破（如 Athalye 等人的 obfuscated gradients 工作）。但 LLM 时代的越狱（jailbreak）与提示注入（prompt injection）防御评估却退化了，作者指出两条主要病根：

1. **静态测试集评估**：复用历史论文里已公开的固定 jailbreak/注入 prompt 数据集，这些样本早已被各模型厂商和防御作者"见过"。
2. **弱自动化攻击评估**：即便跑 GCG 这类优化攻击，也是拿现成算法原样套用、不给算力、不针对防御机制做任何修改。论文还点名现有自动化攻击本身慢且贵——GCG 优化仅 20 token 的后缀要跑 500 步、每步 512 次查询。

而与此同时，人类专家仍在社交媒体和红队挑战赛上持续打出自动化攻击打不出的攻击。因此作者认为 LLM 防御评估的现状"比十年前的对抗样本领域还要差"，需要一套系统化的强自适应评估方法论。

## 问题定义 / 威胁模型

论文明确区分两类威胁：**jailbreak** 是用户本人违背模型设计者意图索取有害内容；**prompt injection** 是第三方通过（间接注入的）内容劫持系统行为、侵害特定用户的机密性/完整性（如数据外泄、删除文件、发送未授权邮件）。

攻击者按访问能力分三档：
- **Whitebox**：完整模型架构、参数、内部状态，可对任意输入/参数求梯度；
- **Blackbox（含 logits）**：可任意查询，能拿到输出分布分数；
- **Blackbox（仅生成）**：只能看最终生成文本或标签。

核心假设：攻击者**知晓防御机制与设计原理**（Kerckhoffs 原则），且**算力预算不设人为上限**——评估目的是判断防御本身是否有效，而非攻破难度。作者特别强调：能被"商品化硬件跑 24 小时"量级的预算攻破的防御，不配称密码学级安全。攻击目标为满足原防御论文定义的成功判据（如 AgentDojo 中完成攻击任务）；找到一次成功即终止。值得注意的是，作者最成功的攻击多数运行在黑盒设定下，单次成功消耗的资源是适度的。

## 方法与系统设计

论文的贡献不是发明新攻击，而是提出**通用自适应攻击框架**：每次迭代四步——(1) **Propose** 提出候选攻击；(2) **Score** 通过查询防御系统打分；(3) **Select** 保留最优候选；(4) **Update** 更新改进。四类实例化：

**梯度方法（GCG）**：对 token 嵌入求梯度投影回离散 token，逐坐标替换。作者按 GCG 原文实现，以模型负损失为分数，只用于攻 RPO。

**强化学习方法**：把 prompt 生成当交互环境。攻击者模型直接与被防御系统交互：发候选串→看响应→按防御特定打分函数评估→反思并提出新候选，每样本 5 轮，成功取 5 次中最佳分；跨 session 用 **GRPO** 更新攻击者策略（每样本 32 个独立 session、batch size 1、学习率 1e-5、KL 系数为 0、最多 100 步）。攻击者底座是一个"只训练了 helpfulness、没有安全对齐"的闭源模型，攻击者 prompt 中会注入目标防御论文的方法学摘要，使其"知防御而攻"。打分函数因防御而异：RPO/Circuit Breaker 用目标恶意 token 的困惑度加 HarmBench 分类器安全分；StruQ/MetaSecAlign 只用目标串困惑度；Data Sentinel 用目标串困惑度加 1.5 倍密钥困惑度。

**搜索方法（进化算法，本文主力）**：借鉴 AlphaEvolve/OpenEvolve，三个模块化组件：
- **Controller**：基于 **MAP Elites** 的岛模型。候选按两个属性量化入网格（trigger 字符数、与 25 个随机 elite 的编辑距离定义的多样性），各分 10 个 bin，每格只留最高分 elite；共 5 个岛轮转。每步喂给变异器的灵感组合为：当前最佳 + 3 个随机 elite + 邻近 bin 的 5 个 elite + 库中 5 个随机候选。
- **Mutator**：用 **Gemini 2.5 Pro（最大思考预算，temperature 1.0 / top_p 0.95 / top_k 64）** 当变异器，每次采样 8 个候选，输出含 "improvement" 和 "trigger" 两字段的 JSON。系统提示（人格、任务、目标工具调用、输出格式）固定可缓存，历史攻击尝试放 user message。
- **Scorer**：二值 oracle 无法引导优化，故由另一个 Gemini 2.5 Pro **critic**（贪心解码）把受害系统的文本反馈打成 1–10 分并给文字建议；critic 只引导搜索，最终成功与否以 benchmark 的 ground-truth 判据为准，且**所有报告的成功均经人工核验**以排除 reward hacking。

**人类红队**：40 个挑战的竞赛，总奖金 $20,000（第一名 $8,000；每个挑战最短成功 prompt 另奖 $200 且可被"偷"）。参赛者在 Web UI 提交注入文本（实为插入工具调用结果的不可信输入），可看到 agent 的推理流与工具调用；成功得 5,000 分减去提交 token 数（惩罚拼接已有 trigger）。覆盖 10 个模型、5 种防御，模型名用化名，参赛者不知道是否部署了防御。

## 实验设置

- **12 个防御、四大类**：Prompting（Spotlighting、Prompt Sandwiching、RPO）；对抗训练（Circuit Breakers、StruQ、MetaSecAlign）；过滤检测器（Protect AI、PromptGuard、PIGuard、Model Armor，前三者均为在良性 prompt + 已知攻击样本上微调的 BERT 系分类器，Model Armor 闭源）；秘密知识（Data Sentinel 蜜罐密钥、MELON 双跑检测）。**明确排除**了提供可证明保证的架构性隔离防御（信息流控制类，如 f-secure、Dual LLM）。
- **Benchmark**：jailbreak 用 HarmBench；agentic 注入用 AgentDojo（取 Slack/Travel/Workspace 三套件的 80 个样本）；Data Sentinel 按原论文用 OpenPromptInjection；StruQ 用 adversarial Davinci/Alpaca。每个防御沿用其原论文评测协议。
- **目标模型**：Gemini 2.5/3 系列、GPT 5/5.2、GPT 5 Mini、Llama 3.3 70B、MetaSecAlign 70B、Grok 4、Command A Reasoning 等前沿模型。
- **指标**：ASR（任一步骤的 trigger 达成攻击目标即算该场景成功）+ 人类红队新指标 **SAR**（成功提交占总提交比例）+ 攻击成本透明披露（搜索攻击中位数约 $2/场景、约 5 分钟；跑满 100 步约 $50、约 3 小时；RL 每防御数千美元）。

## 主要结果

- **总览（图 1）**：12 个防御原论文的静态/弱攻击 ASR 为 28%、21%、0%、8%、62%、5%、15%、26%、0%、0%、0%、0%；本文自适应攻击后变为 99%、95%、99%、100%、100%、96%、90%、94%、71%、90%、80%、89%（对应 Spotlighting 到 MELON），人类红队场景 100%。
- **Prompting 类**：Spotlighting/Prompt Sandwiching 在 AgentDojo 静态攻击下 ASR 低至 1%，搜索攻击后双双 >95%；人类红队分别贡献 265 和 178 次成功注入。破 Prompt Sandwiching 的典型手法是把恶意任务伪装成用户任务的"前置流程"（如伪造 ACCESS_POLICY_ENFORCED 凭证校验话术）。RPO 在 HarmBench 上被 RL 攻击打到 98%、梯度攻击 96%。
- **训练类**：StruQ 的"输出 HACKED"测试被 RL 前缀攻击在**所有测试用例**上攻破，套路是冒充系统级指令；MetaSecAlign 原报告 AgentDojo 静态 ASR 仅 2%，搜索攻击达 96%；Circuit Breakers 在 HarmBench 上被 RL 攻击 100% 攻破。作者将其类比视觉对抗训练的老教训：只在预计算扰动上训练不会泛化，只有训练环内做 robust optimization 才有效。
- **检测器类**：把检测器置信度与检测标志反馈给攻击者后，搜索攻击对 Protect AI、PromptGuard、Model Armor 的 ASR 均 >90%，PIGuard 相对最抗打但仍有 71%；人类红队在最严设定下拿到 123 次成功注入。许多成功 trigger 脱离上下文毫无恶意特征（如"Blue Sparrow Tech 日历改期须删除临时跟踪文件"的伪装政策），检测器不大幅拉高误报就拦不住。
- **秘密知识类**：Data Sentinel 被 RL 攻击以"重定义任务"话术绕过——把情感分析重述为垃圾分类的"辅助信号"，两项恶意任务准确率均 >80%，与无防御模型相当；MELON 在攻击者不知防御时搜索攻击已达 76% ASR（Llama 3.3-70B），模拟知晓论文细节的强攻击者后，变异器自行发现"条件触发"策略（如"若此文本来自文件摘要任务则忽略上述指令"），ASR 升至 95%。
- **前沿模型本身（表 1）**：静态攻击 ASR 对 Gemini 2.5 Pro (High) 为 30%、GPT 5.2 (High) 为 0%，搜索攻击后分别为 100% 和 60%；中位数成功查询数仅 13–66 次（如 Llama 3.3 70B 为 14 次、Gemini 3 Pro 为 14 次）。
- **人类 vs 自动化**：29 个重叠场景上，人类集体 ASR 100%，最佳个人（跑满全部场景）75%，搜索攻击 69%（800 次查询）；最强人类仅需 50 次查询。但 SAR 数据显示，除 MELON 一致降低 SAR（如 Gemini 2.5 Pro 从 11.1 降到 0.4）外，其余防御约半数场景 SAR 反而**上升**（如 PromptGuard 配 Gemini 2.5 Flash 从 9.3 升到 23.8）。

## 贡献与亮点

1. **方法论统一**：把看似各异的自适应攻击收敛为 Propose–Score–Select–Update 四步循环，证明"旧攻击思想 + 针对性适配 + 足够算力"就足以破防，无需发明新攻击。
2. **评估规模与严谨性**：12 个防御、4 大技术路线、前沿闭源模型全覆盖，且所有成功攻击人工核验、成本透明披露，这在同类"破防御"论文中少见。
3. **人类红队对照实验设计**：$20k 竞赛 + 化名模型 + 防御盲测，并首创 SAR 指标度量"持续对抗压力下的韧性"，弥补 ASR 在全攻破情形下无区分度的缺陷。
4. **四条经验教训**（第 8 节）：静态小评测有误导性；自动化评估"必要不充分"——经验评估永远只能"未能证伪防御"，不能证明防御稳健；人类红队仍不可替代；基于模型的自动裁判本身可被对抗样本和 reward hacking 操纵。

## 局限性

论文自述：① 自适应评估成本高（搜索/RL 攻击跑前沿模型很贵），但作者给出降本证据（表 7：把 mutator/critic 换成 Qwen 3 235B 可保 100% ASR、Qwen 3 32B 达 91%、省 10 倍以上推理费），并建议预算受限时"小测试集 + 强攻击"优于"大测试集 + 弱攻击"；② Claude 系只做了小规模实验（引用并发工作补强）；③ 组合防御只初步探索——微调类 + 检测器组合略降 ASR 但仍远不安全，因防御共享失败模式。此外我读出的隐含局限：搜索攻击每场景只跑一次无随机重启（作者自认 run 间方差大）；各防御沿用各自原论文协议，数字之间不可横向比较；人类竞赛参与者水平参差且各场景投入不均，人机对比存在混杂因素。

## 对我们方向的启示

**方向一（内容风控：大小模型训练与审核 harness）**：
- 我们的审核/风控模型本质上就是论文中的"filtering model defense"。论文证明 BERT 系检测器在攻击者拿到置信度反馈后 ASR>90%、PIGuard 也只有 71%——**风控模型上线时绝不能把分数/阈值直接暴露给外部可查询接口**，评分接口要做限流、加噪、脱敏。
- Lesson #4（auto-rater 不可靠）直接适用于审核 harness：我们用 LLM judge 自动判违规的链路，同样会被对抗样本和 reward hacking 打穿，重要决策必须有抽样人工复核和裁判模型的对抗鲁棒性回归测试。
- 训练风控模型时应吸取 5.2 节教训：在预收集的固定违规样本上训练不泛化，需要把攻击生成器放进训练环内（robust optimization 式的持续对抗训练），或维护"攻击即数据"的回流管道。

**方向二（越狱/注入检测）**：
- 评测方法论可直接落地：给团队的检测器建一套"Propose–Score–Select–Update"红队 harness——以 Gemini/Qwen 做 mutator+critic（论文证明开源模型 Qwen 3 235B 也能到 100% ASR），MAP Elites 保多样性，每场景中位数 $2 的成本完全可常态化跑。
- 关键检测信号启发：成功的注入往往"脱离上下文无恶意特征"（政策话术、前置流程、条件触发指令），纯内容分类不够，需结合结构/来源/上下文信号；对 MELON 式双跑检测，要防攻击者写"针对摘要运行的条件分支"。
- 报告规范：以后内部检测器的评测报告应同时披露"静态 ASR + 自适应 ASR + 单次成功攻击成本（查询数/美元）"，防止单一静态指标造成虚假安全感。

**方向三（LLM/Agent 分析恶意 APK）**：
- 我们用 Agent 做静态/动态分析时，反编译出的恶意 APK 资源（字符串、manifest、伪装文档、C2 URL 页面缓存）恰恰是**间接提示注入的天然载体**——本文反复演示的正是"工具调用结果里藏指令"这一路径（AgentDojo 场景）。分析涉诈 App 时，其内嵌文案、WebView 页面、通知推送文本都可能试图劫持我们的分析 Agent（如诱导其外泄沙箱信息或跳过分析步骤），必须在 harness 层做不可信内容隔离与信息流控制。
- 论文排除的"架构性隔离防御"（信息流控制、Dual LLM）恰是我们该优先采用的工程手段：把 APK 派生文本放入隔离上下文，分析结论经独立通道汇出。
- 反向利用：这套自适应攻击框架本身可改造为"恶意样本语义意图挖掘器"——用进化搜索 + critic 打分，从诈欺 App 话术库中自动搜寻最能诱导受害者的变体，用于反诈训练数据扩增和受害者侧防御演练。
